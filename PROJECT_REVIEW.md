# Аудит MindTrack

## Исходное состояние

Проект был персональным трекером с клиентским роутером, регистрацией,
JWT-сессиями, API Routes, Prisma/SQLite, зашифрованным дневником, ответами
опросников и генерацией отчётов. Публичный интерфейс фактически жил на `/`,
а справочные коды тестов находились в seed-данных: `PHQ9`, `GAD7`, `MDQ`,
`ASRS`. Эти коды сохранены в виде стабильных редакционных записей
`scale-phq9`, `scale-gad7`, `scale-mdq`, `scale-asrs` и URL-slug.

## Выполненная миграция

Удалены аккаунты, авторизация, cookies, middleware-подобная серверная логика,
API Routes, server actions, Prisma, миграции, локальная БД, персональный
прогресс, дневник, PDF и share-ссылки. Каталог теперь собирается из
типизированных статических данных и работает без сервера.

Публичные маршруты: `/`, `/topics`, `/topics/trevoga`,
`/topics/nastroenie`, `/topics/vnimanie`, `/topics/son`,
`/scales/phq-9`, `/scales/gad-7`, `/scales/mdq`, `/scales/asrs-v1-1`,
`/favorites`, а также `404.html`, `sitemap.xml`, `robots.txt`.

## Риски и редакционные задачи

Содержимое шкал требует отдельной редакционной проверки и лицензирования
переводов перед публичным позиционированием как медицинского материала.
Поля со статусом `pending` намеренно не называют сведения подтверждёнными.
